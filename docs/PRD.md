# workbuddy-checkin 产品需求文档（PRD）

> 一个 Windows 桌面小工具：管理 CodeBuddy（腾讯，`copilot.tencent.com`）账号并自动完成每日签到。
> 目标仓库：`github.com/hosea3000/workbuddy-checkin`（独立仓库，不与 work2api 互通）。

## 1. 背景与目标

CodeBuddy 每天签到可获得积分（额度）。现有做法是部署一个网关（work2api）跑定时签到，对只需要「签到」的用户过重：要服务器、要配数据库、要开端口。

本产品把「登录 CodeBuddy 账号」+「每日签到」两件事做成一个 Windows 桌面应用，提供两种形态：

- **安装版**：中文安装向导（per-user，装到 `%LOCALAPPDATA%`，无需管理员），自动创建快捷方式与卸载项，支持应用内一键检查更新
- **绿色版**：单文件 exe，免安装，双击即用

共同能力：

- 常驻系统托盘，到点自动签到，电脑没开时开机补签
- 图形界面管理账号（OAuth 登录、查看今日签到结果）
- 数据只存本机（`%APPDATA%\workbuddy-checkin`）

### 成功标准

| 指标 | 目标 |
|---|---|
| 首次使用到完成第一个账号登录 | ≤ 1 分钟，无需看文档 |
| 日常签到成功率（电脑当天开机） | 100%（自动触发 + 补签 + 重试） |
| 电脑关机一天后开机 | 当天自动补签 |
| 用户日常操作 | 0 次（打开即已签到） |
| 崩溃/数据丢失 | 凭证文件损坏不导致应用不可用 |

## 2. 目标用户与场景

**用户**：拥有 1~3 个 CodeBuddy 个人账号、想在 Windows 上自动签到的个人用户。会用浏览器登录 CodeBuddy，不要求懂命令行。

**核心场景**

1. **首次配置**：下载安装器 → 双击安装（中文向导）→ 从桌面图标启动 → 点「添加账号」→ 浏览器登录 → 回来看见账号卡片「今日已签到」→ 勾选开机自启 → 关闭窗口（进托盘）。绿色版用户下载 exe 直接双击。
2. **日常**：开机 → 应用自启静默进托盘 → 09:30 自动签到 → 弹一条通知「签到成功，+5 积分」→ 用户什么都不用做。
3. **漏签补救**：电脑 09:30 时关机，11:00 开机 → 应用启动即发现今天没签 → 自动补签 → 通知。
4. **凭证过期**：CodeBuddy 的 refresh_token 失效 → 卡片变红「需重新登录」+ 通知 → 用户点「重新登录」，浏览器走一遍 OAuth 即可。
5. **查看结果**：打开主界面看到每个账号的今日签到状态与积分余额。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 账号 / 凭证 | 一个 CodeBuddy 账号的 OAuth 令牌集合（access_token + refresh_token + 身份信息） |
| 签到 | 调用上游 `/billing/meter/daily-checkin`，每个账号每个自然日一次，上游幂等 |
| 补签 | 应用启动/唤醒时，发现「已过签到时间且今天未成功签到」立即执行的一次签到 |
| 签到时间 | 每日自动签到触发点，默认 09:30（本地时区），可配置 |
| 需重新登录 | 凭证的 refresh_token 也被上游拒绝，无法自动续期，必须人工重新走登录流程 |
| 托盘驻留 | 主窗口关闭但应用仍在运行、仍在调度签到 |

## 4. 功能需求

### F1 账号登录（OAuth 设备授权）

- 主界面「添加账号」→ 弹窗展示授权链接，**同时自动用系统默认浏览器打开**该链接
- 用户在浏览器完成 CodeBuddy 登录，应用后台轮询（间隔 5 秒）
- 登录成功后凭证自动入库，弹窗自动关闭，卡片列表出现新账号
- 弹窗提供：复制链接、重新打开浏览器、取消
- 授权链接 10 分钟未完成则失效，提示「已过期，请重试」
- 同一账号重复登录：**原位更新凭证**（视为续命），不产生重复卡片，提示「账号已存在，凭证已更新」
- 上游业务错误需给出人话提示（不是原始错误码）：
  - `12005` 企业许可证没有可用席位
  - `11212` CodeBuddy 许可证已过期
  - `11216` 试用授权已过期
  - `10081` 当前 IP 被访问策略限制
- 登录过程中的 access_token / refresh_token **不得出现在界面、日志、通知**中

### F2 账号管理

- 卡片列表展示：昵称（无昵称显示 user_id 短码）、邮箱、状态徽章、今日签到状态、积分余额、凭证有效期
- 积分余额：应用启动时、签到成功后、每 1 小时自动刷新；卡片上可点击手动刷新
- 余额查询失败不影响签到，卡片保留上次的值（从未成功过则显示「—」）
- 卡片操作：立即签到、删除（二次确认）
- 多账号支持（建议上限 20，超出仅提示不建议）
- 删除只删本地凭证，不涉及上游

### F3 手动签到

- 卡片「立即签到」按钮：点击后按钮进入 loading，结果原地更新
- 结果反馈：
  - 成功：显示「已签到 HH:MM，+N 积分」（N 可能没有，则不显示积分）
  - 今日已签：显示「今日已签到」（不算失败）
  - 失败：显示失败原因（网络异常 / 上游 5xx / 限流 / 需重新登录）
- 手动签到同样更新凭证上的今日状态

### F4 每日自动签到

- 触发：每日 `签到时间`（默认 09:30，本地时区）
- 多账号：逐个签到，账号之间随机间隔 5~20 秒（防风控）
- 幂等：凭证记录显示今天已成功签到则跳过；上游返回「已签到」视为成功
- 通知（可关）：成功 → 「签到成功」+ 账号名 + 积分；失败 → 「签到失败」+ 原因
- 失败自动重试（可关）：间隔 30 分钟，当天每账号最多 3 次；`需重新登录` 类失败不重试
- 电脑休眠错过触发点：唤醒后按补签逻辑处理

### F5 补签

- 触发时机：应用启动时、系统从休眠/睡眠唤醒后、跨天后
- 条件：`补签开关开启` && 当前时间已过签到时间 && 今天该账号未成功签到
- 行为：与自动签到一致（逐个、抖动、通知、失败重试）
- 补签开关默认开启

### F6 凭证自动续期

- 判定：`expires_at - now < 24 小时` 且 refresh_token 存在
- 触发时机：应用启动时、每次签到前、签到完成后
- 成功：静默更新 access_token（refresh_token 会轮换，一并保存）
- 失败且为 401/403/refresh_token 被拒：账号标记 `需重新登录` + 托盘图标提示 + 通知一次
- `需重新登录` 的账号：卡片红色徽章 + 「重新登录」按钮，自动签到跳过该账号

### F7 设置

| 设置项 | 默认 | 说明 |
|---|---|---|
| 签到时间 | 09:30 | 时:分，本地时区 |
| 启动时补签 | 开 | F5 |
| 失败自动重试 | 开 | F4 |
| 成功通知 | 开 | Toast |
| 失败通知 | 开 | Toast |
| 开机自启 | 首次向导询问（默认勾选） | HKCU Run，无需管理员 |
| 关闭窗口时最小化到托盘 | 开 | 关闭 = 隐藏，首次提示一次 |
| 启动时检查更新 | 开 | 设置页也可手动检查 |
| 打开数据目录 | 按钮 | 资源管理器打开 `%APPDATA%\workbuddy-checkin` |

### F8 托盘与系统集成

- 托盘菜单：打开主界面 / 退出
- 托盘 tooltip：`workbuddy-checkin — 今日已签到 2/2` 或 `— 有账号需重新登录`
- 双击托盘图标 = 打开主界面
- 关闭主窗口 → 隐藏到托盘（不退出）；**退出只能从托盘菜单触发，且必须真正结束进程——不得只移除托盘图标或隐藏窗口**
- 单实例：重复双击 exe 只唤起已有窗口，不启动第二个调度器
- 开机自启时静默启动（不弹窗），直接进托盘
- 开机自启写入 HKCU；安装版通过控制面板卸载，绿色版删 exe + 关闭自启开关

### F9 更新

- 启动时按「启动时检查更新」设置检查 GitHub Release 最新版本，设置页可手动检查
- 发现新版本时顶栏显示「发现新版本 vX.Y.Z」
- 点击 → 下载新版 exe → 一键替换重启（复用 health-tool 的 updater 方案）
- 更新下载到 exe 同目录，退出后覆盖自身并重启；目录不可写时提示前往 GitHub 手动更新

### F10 首次运行引导

- 首次启动（无凭证文件）显示欢迎页：
  1. 一句话说明工具做什么
  2. 「添加账号」按钮（直接进 F1）
  3. 开机自启勾选（默认勾选）
- 不显示任何需要用户理解的配置项

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 平台 | Windows 10 1809+ / Windows 11，x64（不做 arm64） |
| 形态 | 安装版（per-user，装到 `%LOCALAPPDATA%\Programs\`，无需管理员）+ 绿色版单文件 exe |
| 体积 | 绿色版 ≤ 15 MB；安装器 ≤ 25 MB |
| 启动 | 冷启动 ≤ 2 秒（自启静默启动 ≤ 1 秒进托盘） |
| 内存 | 常驻 ≤ 80 MB |
| 数据 | 全部在 `%APPDATA%\workbuddy-checkin\`，不上传任何第三方 |
| 网络 | 仅访问 `copilot.tencent.com` 与 GitHub（更新检查/下载，可关） |
| 隐私 | 令牌仅本地明文存储（0600 权限）；日志/通知/界面不出现令牌 |
| 时区 | 签到日期与时间一律取本机本地时区 |
| 鲁棒 | 配置文件损坏时：备份为 `.corrupt` 后以空数据启动，不阻塞应用 |
| 卸载 | 安装版：控制面板卸载（默认保留 `%APPDATA%` 数据）；绿色版：删 exe + `%APPDATA%` 目录 + 关闭自启开关 |

## 6. 明确不做（本期）

- TRAE / 其他 provider（只做 CodeBuddy CN）
- 与 work2api 互通、导出令牌、OpenAI 兼容接口、聊天/模型功能
- 多用户 / 团队 / 云端同步 / 账号共享
- 国际版 `www.workbuddy.ai` 账号（无签到体系）
- 自动更新（已实现，见 F9）
- macOS / Linux 发行版（仅保留 Linux 下可开发的 stub）
- 代码签名、MSI / 企业批量部署

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 上游接口为逆向所得，可能变更 | 签到/登录失效 | 移植 work2api 已验证实现；错误分类明确；失败通知用户而非静默 |
| 上游风控（同 IP 多账号） | 账号受限 | 账号间 5~20s 抖动；不并发；不轮询无关接口 |
| refresh_token 过期 | 无法自动续期 | 临期 24h 主动刷新 + 到期提醒重新登录 |
| 电脑长期关机 | 漏签 | 补签（F5）；不做任务计划（用户明确选择托盘+补签） |
| 杀软误报（未签名 exe/安装器 + 网络行为） | 用户流失 | 开源可查；README 说明；不写注册表敏感位置（仅 HKCU Run） |
| 免责 | — | README 声明：仅限本人授权账号、本机使用 |

## 8. 验收清单（人工）

1. 全新 Windows 环境双击 exe → 首启引导 → 添加账号 → 浏览器登录 → 卡片出现且显示「今日已签到」
2. 关闭窗口 → 应用仍在托盘；双击 exe → 唤起窗口（不重启）
3. 设签到时间为 1 分钟后 → 到点自动签到 + Toast 通知
4. 关闭应用 → 把系统时间调到签到点之后 → 启动应用 → 立即补签
5. 断网状态下点「立即签到」→ 显示网络异常，30 分钟后自动重试
6. 手工破坏 `credentials.json` → 启动应用 → 备份 `.corrupt` 并正常进入引导页
7. 勾选开机自启 → 重启 Windows → 托盘出现应用且未弹窗
8. 托盘菜单「退出」→ 进程消失；自启开关关闭后重启不再出现
9. 账号列表含 2 个账号 → 自动签到按 5~20s 间隔逐个执行，通知各一条
10. 卡片显示积分余额；签到成功后余额随之更新；点卡片刷新按钮立即更新；断网时余额请求失败但签到结果正常
11. 普通用户（非管理员）运行安装器 → 无 UAC → 中文向导 → 桌面/开始菜单快捷方式与卸载项生成 → 控制面板可卸载
12. 安装版发现新版本 → 设置页「立即更新」→ 下载进度 → 确认重启 → 版本号变为新版本；绿色版同流程（目录可写时）

## 9. 里程碑

| 阶段 | 内容 | 可演示 |
|---|---|---|
| M1 | Wails 骨架 + 托盘/自启/单实例 + 空壳 Vue3 界面 | 双击运行、托盘驻留 |
| M2 | 上游客户端移植 + OAuth 登录闭环 + 凭证存储 | 能添加账号并看到卡片 |
| M3 | 手动签到 + 今日状态 + 卡片状态 + 通知 | 能签到、卡片状态正确 |
| M4 | 调度 + 补签 + 重试 + 凭证续期 | 关掉应用再开，自动补签 |
| M5 | 设置页 + 引导页 + 更新器 + CI 发布 | 打 tag 出 Release exe + 中文安装器 |

M1~M4 为可发布的最小可用版本（v0.1.0），M5 为 v0.2.0。

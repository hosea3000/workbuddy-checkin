## Context

账号卡片余额区两行由 `balance`（数值，`toLocaleString('zh-CN')`）与 `balanceSub`（`积分余额 · HH:MM` 或仅有 `积分余额`）两个计算属性渲染。标签与时间用 `·` 拼接，且标签在数值下方，导致「值 / 单位 / 时间」归属歧义。

约束：沿用 Tailwind v4 与既有排版 class，不引入新依赖，不改绑定方法与 store。

## Goals / Non-Goals

**Goals:**
- 数值与单位同行，时间独立成行并带上「刷新」语义。
- 无时间时占位不跳行；无余额时行为明确。

**Non-Goals:**
- 不改 `⟳` 刷新按钮（已有 `刷新余额` hover 文案）。
- 不改余额刷新成功 toast 与 `refreshQuota` action。
- 不引入相对时间（如「3 分钟前」）或轮询换算逻辑。

## Decisions

### 两行结构

| 方案 | 第一行 | 第二行 | 取舍 |
|---|---|---|---|
| A（选定） | `1,234 积分` | `09:30 刷新` | 单位紧跟数值、时间带「刷新」语义，最短且无歧义 |
| B | 小字标签 `积分余额` / 大号 `1,234` | 时间 | 层次最强，但三行抬高卡片，与行尾图标不对齐 |
| C | `1,234` | `积分余额 · 09:30 刷新` | 改动最小，但保留了「标签在下」的原始歧义 |
| D | `1,234 积分` | `余额更新于 09:30` | 语义更完整，但文案偏长，窄窗口易挤压 |

选用 A。

### 空态

- 无 `creditBalanceAt`：第二行渲染空字符串，仍占用一行高度 → 不跳行（用户选定）。
- `creditBalance == null`：第一行仅 `—`，不附加单位（用户选定）。

实现上 `balanceSub` 从「标签+时间」改为「时间 + 刷新」，空值返回空串；`balance` 追加单位但 `—` 时除外。

替代方案：用 `min-h` 固定时间行高度而非渲染空串——被否，二者等价的视觉效果下，渲染空串更简单。

## Risks / Trade-offs

- [`09:30 刷新` 中「刷新」是名词性表述，可能与旁边 `⟳` 按钮动作语义混淆] → `⟳` 的 hover 文案为「刷新余额」，且时间行不可点、颜色更浅；接受。
- [第二行为空时留白，略占空间] → 换取行高稳定，用户已确认接受。
- [无余额时显示 `—`，与「有余额但未刷新」形态不同] → `—` 本身已无单位可误导，接受。
